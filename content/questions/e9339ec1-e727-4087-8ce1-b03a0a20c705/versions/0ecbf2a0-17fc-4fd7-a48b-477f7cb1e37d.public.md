## 问题诠释

长期与 Agent 协作时，用户会不断提出要求、纠正理解，并补充具体情境。把这些经验整理成可复用的 Skill，通常要经过 Session 总结、多份总结合并，以及按写作指南精简重构。

问题在于：这些转换可能保留相似的措辞，却逐渐改变用户真正要求的内容。信息损失既可能发生在第一次总结，也可能在成型 Skill 的后续重写中进一步加重。

例如，“主动选择适合品牌调性和表达内容的字体”可能被替换成“检查已有字体的排版”。即使字号、字距和换行全部检查通过，也不代表认真进行过字体选择。这种变化不是简单的文字压缩，而是把必须执行的动作换成了另一个动作。

## 这里的“保真”指什么

提取出的 Skill 应保留原要求的含义、约束强度和必须执行的动作。明确禁止的事项，不应被自行改成有例外的建议；要求专门完成的步骤，不应被弱化成“有需要时可以做”。

同时，Skill 需要能在后续任务中执行。仅保留关键词或复述原话，不足以说明它已经准确承接了用户意图。

## 想研究的问题

如何从长期 Agent Session 中提取可复用经验，在总结、合并和重写的过程中保留用户原意，并判断最终 Skill 是否仍要求 Agent 做同样的事？

需要特别关注两层转换：

- **Session → 总结**：首次提取时，哪些要求被遗漏、改写或弱化了？
- **成型 Skill → 按写作指南重写**：后续精简是否进一步改变了含义、强度或执行动作？

我希望找到一种可核查的提取和转化方式，使 Skill 在变得简洁、可复用的同时，仍然忠实于用户实际提出的要求。

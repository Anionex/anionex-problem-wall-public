## 问题从哪里来

这两天，我一直在设计和改写自己网站的前端。经过一长串与 Agent 协同驾驶的 coding 之后，我想把长期交互中形成的设计要求和经验整理成可复用的 Skill。

我的做法是先让 Codex 总结各个 session，再把总结合并写成 Skill，之后按照 Skill 写作指南（Meta Skill）精简重构。后来回查才发现：这些内容在逐层整理中，已经逐渐偏离了我的原意。

## 一个最明显的例子：字体

字体是我最重视的要求之一。我明确说过：

> 每一个组件都要经过刻意的设计考虑……如果有文字，用什么字体。

我还强调过：

> 字体选择很重要……必须要根据品牌调性和表达内容选择最适合的字体。

我要求的是**主动选择字体**，最后却变成了**检查已有字体的排版**。即使字号、字距、换行全部检查通过，也可能从头到尾没有认真选过字体。

## 有些要求在第一次总结时就变了

- 我说“禁止系统默认”，它解释成了“禁止未经判断的默认结果”。
- 我要求完成后**专门逐项做减法**，它只留下“不必要的元素可以删除”。

这些变化不只是把文字缩短：要求本身的含义、强度和必须执行的动作也发生了变化。

## 两层信息损失

第一层发生在 **Session → 总结**：第一次提取经验时，就已经丢失或改写了一部分原意。

第二层发生在 **成型的 Skill → 按写作指南重写**：再经过一次精简重构，信息损失变得更加严重。

从实际、长期的 Agent 交互中提取可复用经验，是一个非常实际的问题。我想研究的是：如何让这套提取和转化过程保留用户真正要求的内容，而不是得到一份看起来更简洁、执行起来却已经偏离原意的 Skill？
